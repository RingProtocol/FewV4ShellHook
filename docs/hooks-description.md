FewV4ShellHook is a Uniswap v4 hook that exposes an origin-token shellPool while routing all actual swap execution through a corresponding FewToken lpPool. For example, an A/B shellPool can route swaps through the existing fwA/fwB lpPool. The shellPool is an interface and settlement layer; it is not used as the swap execution venue and does not add an additional fee.

During beforeSwap, the hook derives the permitted lpPool route, wraps the origin input into the corresponding FewToken, executes the swap against the lpPool, unwraps the FewToken output, and returns the resulting BeforeSwapDelta to the shellPool. Both exact-input and exact-output swaps must fill completely. If the route is unavailable, the lpPool has no active liquidity, required inventory is insufficient, or the swap cannot be fully executed, the transaction reverts. The hook never falls back to the shellPool or to an arbitrary user-supplied pool.

The lpPool route is either registered by the owner for an initialized shellPool or derived from the FewFactory wrapped-token mapping. Explicit registrations are validated to ensure that the FewToken wrappers correspond to the shellPool currencies. Callers cannot select or override the route through function arguments or hookData. The lpPool may have its own configured hook when explicitly registered, subject to the existing restriction against beforeSwapReturnDelta hooks. The route remains restricted to the registered PoolKey.

Uniswap or an aggregator can discover the shellPool's available depth through the IAggregatorHook interface. For an initialized shellPool PoolKey, compute its PoolId using the standard Uniswap v4 PoolKey hashing method, then call pseudoTotalValueLocked(PoolId) on the Hook. The ABI is:

function pseudoTotalValueLocked(bytes32 poolId) external view returns (uint256 amount0, uint256 amount1)

The Hook also exposes quote(bool zeroToOne, int256 amountSpecified, bytes32 poolId) through IAggregatorHook. Negative amountSpecified represents exact input and positive amountSpecified represents exact output. The quote simulates the complete shellPool swap, including the internal lpPool swap, PoolManager input inventory, output backing, wrapping, unwrapping, and full-fill checks. It models swap-before-payment: a prepaid transaction may be executable even when this conservative quote rejects insufficient starting inventory. It is intended to be called through eth_call because the underlying V4Quoter uses revert-based simulation and is intentionally not declared view. The simulation does not persist state or consume transaction gas when used through eth_call.
